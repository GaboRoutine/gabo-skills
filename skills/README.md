# skills/

Canonical, tool-agnostic source of skills. **One directory per skill**, each with a
`SKILL.md` and any bundled assets (scripts, reference docs, checklists). `install.py`
reads these and generates the right format for every target tool.

```
skills/
  module-boundary-check/
    SKILL.md                  # frontmatter + instructions (the canonical skill)
    reference.md              # bundled asset — extra context, loaded on demand
    scripts/check_boundaries.py   # bundled asset — a runnable script
  commit/
    SKILL.md                  # a skill with no assets is just a SKILL.md
```

## SKILL.md format

```markdown
---
name: skill-name              # required; directory name is the fallback
description: one-line summary # required; tools read this to decide when to load it
globs:                        # optional; file patterns the skill applies to
  - "**/*.py"
always: false                 # optional; true = always-applied rule

# Claude Code-only fields (ignored / best-effort elsewhere)
allowed-tools: Read, Bash(git *)   # pre-approved tools
argument-hint: "[issue-number]"    # shown in autocomplete
disable-model-invocation: true     # only the user can invoke, not the model
when-to-use: |                     # extra trigger phrases
  Use when the user …
---

# Skill body in markdown

Instructions go here. Reference a bundled script with the ${SKILL_DIR} token —
the installer rewrites it to wherever the script lands for each tool:

  !`python3 ${SKILL_DIR}/scripts/check_boundaries.py ${ARGUMENTS:-./gabo}`
```

### `${SKILL_DIR}` — portable script references

Bundled scripts live at different paths per tool. Write `${SKILL_DIR}/scripts/x.py`
in the body and the installer substitutes the real location:

| Tool | `${SKILL_DIR}` becomes |
|---|---|
| Claude Code | `.claude/skills/<name>` |
| Cursor | `.cursor/rules/<name>` |
| Windsurf | `.windsurf/rules/<name>` |
| Copilot | `.github/instructions/<name>` |
| Codex | `.agents/skills/<name>` |

The token `${ARGUMENTS}` (and `$ARGUMENTS`) is left untouched — only `${SKILL_DIR}`
is rewritten.

### Claude Code dynamic context

A line beginning with `` !` `` runs a shell command and inlines its output before
Claude reads the skill (Claude Code only — elsewhere it appears as literal text, still
useful as a "run this" instruction). `$ARGUMENTS` expands to whatever follows the
`/skill-name` invocation.

## How each skill lands per tool

| Tool | File written | Assets |
|---|---|---|
| Claude Code | `.claude/skills/<name>/SKILL.md` | copied into the skill dir |
| Cursor | `.cursor/rules/<name>.mdc` | copied to `.cursor/rules/<name>/` |
| Copilot | `.github/instructions/<name>.instructions.md` | copied alongside |
| Windsurf | `.windsurf/rules/<name>.md` | copied to `.windsurf/rules/<name>/` |
| Codex | section in `AGENTS.md` | copied to `.agents/skills/<name>/` |

## Conventions

- Keep skills short — under ~100 lines. Long skills don't get loaded reliably.
- One concern per skill. "Python style" and "commit messages" are two skills.
- Lead with the rule, then a *Why* / *How to apply* when the reasoning isn't obvious.
- `disable-model-invocation: true` for anything with side effects (commits, deploys).
- Put bundled scripts under `scripts/` and reference them with `${SKILL_DIR}`.

See also: `../agents/` (subagents), `../personas/` (output styles), `../config/`
(CLAUDE.md, settings, MCP, worktreeinclude). All are generated by `../install.py`.
